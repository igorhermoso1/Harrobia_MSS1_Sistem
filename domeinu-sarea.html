Laborategiaren helburua eta arkitektura

04 · IDENTIFIKAZIOA

Zerbitzariaren izena aldatzea eta egokitzaileak identifikatzea

Active Directory instalatu aurretik, komeni da zerbitzariaren izena aldatzea eta bi sare-egokitzaileak zein den bakoitza identifikatzea.

~/identifikazioa.txt

Izena aldatu (WS19)

💡 VirtualBox-en aholku praktikoa: makina birtualaren barruan saioa hasteko Ctrl+Alt+Supr sakatu behar denean, gogoratu Ctrl (eskuinekoa) + Supr erabili behar dela (VirtualBox-en ostalari-tekla ordezkatzen baitu eskuineko Ctrl-ak); horrela bidaliko zaio agindua makina birtualari, ez ostalari-ordenagailuari.

Lehenetsi gisa, Windows Server-ek ausazko izen bat esleitzen dio ekipoari (adibidez, WIN-8JH3L2M). Praktika ona da izen hori Active Directory instalatu aurretik aldatzea; izan ere, ondoren domeinu-kontrolatzaile baten izena aldatzea askoz konplexuagoa da.

  1. Zerbitzariaren kudeatzailea (Server Manager) → Tokiko zerbitzaria (Local Server).
  2. Erdiko zatian hainbat propietate agertuko dira: ekipoaren izena, lan-taldea, Ethernet, Windows Update, IE segurtasun hobetua, eta abar. Klik egin "Ekipoaren izena" atalean.
  3. Sistemaren propietateak leihoan, sakatu "Aldatu..." eta idatzi WS19.
  4. Onartu; Windows-ek berrabiarazi beharra dagoela adieraziko du. Onartu berriro eta berrabiarazi.

Berrabiarazi ondoren, izena egiaztatu cmd-tik: hostname edo echo %computername% — WS19 itzuli behar du.

Sare-egokitzaileak identifikatu eta izenez aldatu

Tokiko zerbitzariaren panelean, Ethernet atala bilatu eta bi egokitzaileak dituen leihoa irekiko da. NAT eta Barne-sarea bereizteko:

NAT

IP mota: 10.0.2.x. Izen berria: "Internet (NAT)".

Barne-sarea

IP mota (konfiguratu aurretik): 169.254.x.x (APIPA). Izen berria: "Barneko LANa".

Izena aldatzeko: eskuineko botoia egokitzailearen gainean → "Aldatu izena".

05 · IP KONFIGURAZIOA

IPv4 konfigurazioa zerbitzarian

"Barneko LANa" egokitzaileari IP finko bat eman behar diogu, gerora domeinu-kontrolatzailearen ardatza izango dena.

~/ipv4.conf
  1. "Barneko LANa" gainean eskuineko botoia → Propietateak → bilatu IPv4 eta aldatu.
  2. IP helbidea: 192.168.100.10. Azpisare-maskara automatikoki agertuko da (255.255.255.0).
  3. Atebidea: hutsik utzi — beste egokitzaileak (NAT) arduratuko da bideratzeaz.
  4. DNS zerbitzaria: zerbitzari honen IP bera (192.168.100.10) — horrela, loopback bat sortzen dugu.
Zergatik bere burua da DNS? Domeinu-kontrolatzaile batek berak eman behar ditu domeinuko izen-ebazpenak (DNS zerbitzu propioa izango baitu Active Directory instalatzean). Horregatik, DNS eremuan bere IP propioa jarri behar da, kanpoko DNSrik ez.

Egiaztatzeko: ipconfig egokitzaileen egoera ikusteko, eta Googleren DNSari ping eginez konexioa badugula ziurtatzeko.

07 · DOMEINU-KONTROLATZAILEA

Zerbitzaria domeinu-kontrolatzaile mailara sustatzea

1️⃣

Inplementazioaren konfigurazioa

2️⃣

Domeinu-kontrolatzailearen aukerak

Utzi funtzio-maila Windows Server 2016-an. Ziurtatu DNS zerbitzaria laukia markatuta dagoela. Idatzi DSRM pasahitza (larrialdietarako, gorde ondo!). Hurrengoa sakatzean, DNS bideratzearen abisu bat ager daiteke: alde batera utzi, ohikoa da baso berri bat sortzean agertzea.

3️⃣

NetBIOS izena eta bideak

Morroiak automatikoki betetzen du NetBIOS izena (adib. IGOR), 15 karakteretara mugatua. NTDS/SYSVOL bideak: utzi lehenetsitakoak.

Sistemak balidazioa egingo du (kontrol-marka berdea = dena ondo). Sakatu Instalatu; zerbitzaria berrabiaraziko da automatikoki.

⚠️ Oso garrantzitsua: Active Directory instalatzean, Windows-ek DNS zerbitzariaren helbidea automatikoki aldatu ohi du 127.0.0.1 (localhost) jartzeko. Berrabiarazi ondoren, berrikusi barne-sareko DNSa eta idatzi berriro zerbitzariaren benetako IP finkoa (192.168.100.10).

08 · KUDEAKETA

Antolaketa-Unitateak (OU) eta erabiltzaileak

Domeinua martxan dagoenean, egitura logikoa sortu behar da erabiltzaileak eta ekipoak antolatzeko.

~/ad/ou-eta-erabiltzaileak.txt

Zer da Antolaketa-Unitate bat (OU)?

"Karpeta adimendun" gisa funtzionatzen duen edukiontzi logikoa da Active Directory barruan. Sareko baliabideak (erabiltzaileak, taldeak, ekipoak) enpresaren hierarkiaren arabera egituratzea ahalbidetzen du (departamenduak, proiektuak, ordezkaritza geografikoak). Abantaila teknikoa: Talde-Direktibak (GPO) ezartzea eta administrazio-baimenak eskuordetzea ahalbidetzen du.

  1. Ezkerreko panelean, domeinu-izenaren gainean klik (adib. igor (local)).
  2. Zereginak → Berria → Antolaketa-unitatea (OU).
  3. Izena jarri (adib. Salmentak, Administrazioa, Ikasleak) eta markatu "Ustekabean ezabatzeko babestu".

Erabiltzailea OU barruan sortu

  1. Sartu sortu berri duzun OUra.
  2. Zereginak → Berria → Erabiltzailea.
  3. Bete izena, abizenak eta erabiltzaile-izena (UPN, adib. jgarcia@igor.local).
  4. Ezarri pasahitza eta markatu "Erabiltzaileak pasahitza aldatu behar du hurrengo saio-hasieran".

Bi tresna, datu-base bera

🖥️ Active Directory Administrazio Zentroa

Interfaze grafiko modernoa; kontuak berrezarri, egitura antolatu, hardwarearen bizi-zikloa kudeatu.

👥 Erabiltzaileak eta Taldeak (dsa.msc)

Tresna klasikoa; OUak kudeatu, erabiltzaile-kontuak kontrolatu (pasahitza aldatzera behartu, pasahitza gaizki sartzeagatik blokeatutako kontuak desblokeatu), segurtasun-taldeak administratu, sareko ekipoak mantendu (langile-baja baten makina desgaitu edo konfiantza-harremana berrezarri).

Bi tresnek domeinuaren datu-base beraren gainean jarduten dute; funtzio operatibo berberak eskaintzen dituzte, itxura ezberdinarekin.

09 · BEZERO-MAKINA

Windows 10 / Ubuntu Dual Boot

Domeinu-kontrolatzailea prest dagoenean, bezero-makina prestatu behar da: disko gogor bera partekatuko duten bi sistema eragile, Dual Boot bidez.

~/dualboot/plan.md

Bi makina birtual independente sortu ordez, makina bakarra sortuko dugu bi sistema eragilerekin: Windows 10 eta Ubuntu 22.04 LTS. Konfigurazio honi Dual Boot (abiarazte bikoitza) deitzen zaio. Ekipo honek ere bi sare-interfaze izango ditu: bata Internetera (NAT), bestea laborategiko domeinu-kontrolatzailearekin komunikatzeko (LAN_MSS).

⚠️ Instalazio-ordena garrantzitsua da: beti instalatu lehenengo Windows eta ondoren Ubuntu. Windows-en instalatzaileak ez ditu beste abiarazte-kudeatzaileak ondo ezagutzen, eta Linux lehenago instalatuz gero, existitzen den abiarazte-kudeatzailea gainidatziko luke. Ubuntuk, aldiz, automatikoki detektatzen du Windows eta GRUB konfiguratzen du bi sistemen artean aukeratzeko.

Praktika ona: ez okupatu disko osoa Windows instalatzean, Ubunturako espazio librea utziz.

  1. Instalatu Windows 10 lehenik, eta egiaztatu ondo abiarazten dela.
  2. Windows-en, ncpa.cpl (Win+R) bidez, egokitzaileak izenez aldatu (NAT ~10.x, LAN ~169.x hasieran) eta LAN egokitzaileari barruko IP finko bat jarri, DNS nagusia zerbitzariarena izanik: 192.168.100.10.
  3. Instalatu Ubuntu, "Instalatu Ubuntu Windows-en ondoan" aukerarekin (edo, agertzen ez bada, partizio berri bat sortuz "+"-rekin).
  4. Ubunturen sare-interfazea ere konfiguratu: Ezarpenak → Sarea → engranaje-ikonoa → IPv4 → Eskuz, barne-sareko IP bat eta DNS gisa zerbitzariaren IPa jarriz.
  5. Konfiguratu GRUB bi sistemen artean aukeratzeko, eta piztu bi makinak (zerbitzaria + bezeroa) hurrengo urratserako.

Zerbitzariaren konfigurazioa

2️⃣

Bezeroaren konfigurazioa

Komandoak eta batzea

11 · BEZEROA (UBUNTU) · METODO GOMENDATUA

Ubuntu domeinura batzea — metodo natiboa (realmd/sssd)

PBIS-Open tresnak arazoak eman ohi ditu laborategi honetan (bereziki DNS/mDNS gatazkak direla eta). Horregatik, gida honek Ubunturen metodo natiboa gomendatzen du (realmd + sssd + adcli), egonkorragoa eta gaur egun ohikoena baita.

~/ubuntu/realmd-join.sh

0. Aurre-egiaztapenak

  • Ziurtatu Ubuntu eta zerbitzaria sare berean daudela: ping 192.168.100.10 egin behar du erantzun.
  • Pakete-kudeatzailea blokeatuta badago (eguneraketa automatikoek utzitako unattended-upgr prozesuagatik), askatu: sudo kill -9 <PID> eta sudo dpkg --configure -a.

1. DNS ebazpena konfiguratu (lehen saiakera)

Ubuntuk igor.local domeinua aurkitu ahal izateko, izen-ebazpenerako fitxategia konfiguratu behar da, zerbitzariaren helbidera bideratuz:

$ sudo nano /etc/resolv.conf # idatzi: nameserver 192.168.100.10 search igor.local
NAT motako egokitzailearekin ari bagara (gure kasua), maiz gertatzen da aldaketa hau berak nahikoa ez izatea — sistemak NATen DNSa lehenesten jarraitzen du, edo fitxategia automatikoki gainidazten da. Horrelakorik gertatzen bada, jarraitu behekoa (2-5 urratsak) lehenik, eta gero, arazoak jarraituz gero, joan zuzenean orriaren amaierako "🛠️ Arazoak konpontzen" atalera, konponbide osoa eta iraunkorra baitakar.

2. Tresnak instalatu

$ sudo apt update && sudo apt install realmd sssd sssd-tools adcli samba-common-bin packagekit -y

3. Domeinua aurkitu eta batu

$ realm discover igor.local # emaitzak "active-directory" mota adierazi behar du $ sudo realm join --user=Administrador igor.local # tokiko sudo pasahitza + Windows Serverreko Administratzailearen pasahitza eskatuko ditu

4. Egiaztatu integrazioa

$ id pgomez@igor.local # uid/gid balioak itzuli behar ditu domeinuko erabiltzailearentzat
Huts egiten badu: realm join huts eginez gero edo id komandoak erantzunik ematen ez badu, arazoa DNS ebazpenean dago ia beti (1. urratseko aldaketa ez da nahikoa izan). Joan zuzenean beheko "🛠️ Arazoak konpontzen" atalera.

5. Saioa erabiltzaile-izen laburrarekin (aukerakoa, erosoagoa)

Domeinura batu ondoren, izen osoa idatzi behar da (pgomez@igor.local). Izen laburra (pgomez) soilik onartzeko:

$ sudo nano /etc/sssd/sssd.conf # [domain/igor.local] blokean, aldatu: use_fully_qualified_names = False $ sudo systemctl restart sssd

6. Sudo baimenak domeinuko erabiltzaile bati eman

$ sudo nano /etc/sudoers.d/usuarios-dominio # fitxategi berrian idatzi: pgomez@igor.local ALL=(ALL:ALL) ALL

🛠️ Arazoak konpontzen (1. urratsa nahikoa izan ez bada)

Bi sare-egokitzaile ditugunean (NAT + Barne-sarea), Ubuntuk sarritan NATen DNSa lehenesten du gure zerbitzariarena baino, eta /etc/resolv.conf-en eskuzko aldaketa hutsa ez da nahikoa izaten (fitxategia automatikoki gainidatz daiteke). Konponbide osoa eta iraunkorra, urratsez urrats:

  1. Tokiko ebazle automatikoa itzali:
    $ sudo systemctl stop systemd-resolved $ sudo systemctl disable systemd-resolved
  2. Egokitzaile bakoitzari DNS zuzena behartu (nmcli): lehenengo, identifikatu konexioen izenak nmcli connection show bidez (adib. enp0s8 = zerbitzariarena, enp0s3 = internetekoa).
    $ sudo nmcli device modify enp0s8 ipv4.dns "192.168.100.10" $ sudo nmcli device modify enp0s8 ipv4.dns-search "igor.local" $ sudo nmcli device modify enp0s8 ipv4.ignore-auto-dns yes $ sudo nmcli device modify enp0s3 ipv4.ignore-auto-dns yes $ sudo nmcli device disconnect enp0s8 && sudo nmcli device connect enp0s8
  3. DNS fitxategia berridatzi:
    $ sudo rm -f /etc/resolv.conf $ sudo nano /etc/resolv.conf # idatzi: nameserver 192.168.100.10 search igor.local
  4. Fitxategia blindatu (inork ez dezan automatikoki gainidatzi):
    $ sudo chattr +i /etc/resolv.conf
  5. Katxea garbitu eta SSSD berrabiarazi:
    $ sudo sss_cache -E $ sudo systemctl restart sssd
PBIS-Open buruz: deck zaharragoan PBIS bidez batzeko aukera ere ageri da (softwarea deskargatu, chmod, ./domainjoin-cli join...). Egiaztatuta dago tresna horrek sarritan huts egiten duela 32 biteko bateragarritasun-karpeta falta delako 64 biteko Ubuntun, eta DNS gatazka berdinak pairatzen dituela.
